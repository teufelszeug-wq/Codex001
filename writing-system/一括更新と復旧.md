# 一括更新と復旧

設定ファイル、世界設定、出典台帳、原稿を一つの変更案として検査・承認する。設定・世界・原稿などの別ファイルを扱うが、OSレベルで全ファイルが同時に置換される機構ではない。処理中は目印を置き、このシステムを通した作品読取を拒否することで中間状態の利用を防ぐ。

## 操作

```text
node writing-system/cli.mjs propose-bundle 作品フォルダ system/一括変更案.json
node writing-system/cli.mjs approve-bundle 作品フォルダ 変更ID system/承認.json
node writing-system/cli.mjs apply-bundle 作品フォルダ 変更ID
node writing-system/cli.mjs recover-bundle 作品フォルダ 変更ID finish
node writing-system/cli.mjs recover-bundle 作品フォルダ 変更ID rollback system/取消根拠.json
```

変更案は changes（pathとcontentの配列）、metadata（reason、meeting_id、decision_ids）を持つ。現在の版について全担当の意見を回収した会議、設定内の変更履歴、承認者と承認根拠が必要。承認記録は本人認証の代わりではない。

## 検査と制限

- 更新前に候補ファイルを別領域へ置いて検査する。作品IDの混入、登録漏れ、不正なパス、対象重複を拒否する。
- 制御ファイル・外部AIの実行設定は一括変更対象外。本文停止中は原稿の変更とシーン進行を拒否する。
- 変更前後の文字列を保存する。中断後は各ファイルが変更前・変更後のどちらかであることを確認して再開する。
- 外部で別の変更が入っていたら、それを上書きせず復旧を止める。中断中に新しい原稿が増えた場合も拒否する。
- 取消時は元の文字列へ戻す。今回新設した対象ファイルだけは元の不存在状態へ戻す。
- 一括変更に任意の削除操作は含めない。新規ファイルの取消以外の削除は対象外。
- 同時変更用のロックが強制終了で残った場合の自動解除、電源断への耐久性、外部エディタによる読取の遮断は未実装・未検証。
- この機能はローカル更新用。GitHubとNotionの更新が同時に成功することは保証しない。

## 完成時の会議

2026-09-18の再開指示を反映し、全システムの完成判定時にソクラテス役・マキャヴェッリ役・ケインズ役・編集者・整合性担当で追加要素を検討する。各要件の実装証拠、不足、反対意見、追加案の優先度を記録する。会議で合意しただけでは実装完了にしない。
