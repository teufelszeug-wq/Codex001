# 世界設定の項目編集と差分

2026-09-25更新。自由文の世界設定案から確定設定を自動生成せず、明示された項目編集を差分確認・一括更新候補へ渡す。コマンド操作と、項目入力・差分確認・候補保存・承認・反映・取消の画面を利用できる。

画面の入口は世界設定案の「項目ごとの変更と差分を確認する」。現在の設定を見ながら項目を入力し、検討済みの会議と変更理由を指定する。「変更前後を確認」は読取のみ。「この内容で反映候補を保存」は承認待ちの候補を作り、正本は変えない。入力変更後は差分の再確認が必要。会議一覧は検査済み・現行基準版・結論保存済みを対象とする。

HTTPで差分入力のハッシュを照合し、入力不足や会議不備は操作記録を作る前に拒否する。同じ操作IDの再送は候補を二重作成しない。通信結果が不明なら再送を止め、企画画面の操作記録と一括更新候補を確認する。ハッシュは本人認証や人間が閲覧した証明ではない。

## 操作

作品フォルダ内の入力JSONを用意し、次の順に操作する。

```text
node writing-system/cli.mjs preview-world-entries 作品フォルダ system/項目変更.json
node writing-system/cli.mjs propose-world-entries 作品フォルダ system/項目変更.json
```

入力には `series_id`、現在の `base`、`entries` を指定。候補作成には `reason` と、検討済みで現在の基準版と一致する `meeting_id` も必要。各entryはcategory、id、value、status、sourcesを持つ。statusはproposal／confirmed／rejected／unknown。出典は空でない文字列の配列。IDは英字で始まる英数字・ハイフン・アンダースコア、最大80文字で、同じ分類内の項目を識別する。

対象はcountries、languages、writing_systems、units、currencies、religions、magic_rules、institutions。地球由来語は異なるデータ形のため、この操作では未対応。項目の削除は扱わず、不採用はrejectedとして記録する。

差分確認は追加／更新と変更前後を返すだけで、作品へ保存しない。候補作成は世界設定と判断履歴を一括更新の候補領域へ保存し、取引IDと差分を返す。変更対象以外の項目・補助属性を保持する。重複ID・欠落出典・別作品・古い基準版・変更なしを拒否する。元データのID欠落・重複がある分類は、推測で移行せず先に資料を確認する。

## 承認と反映

候補作成だけでは正本は変わらない。返された `transaction.id` を既存の `approve-bundle`、`apply-bundle`、必要なら `recover-bundle` へ渡す。操作仕様は「一括更新と復旧.md」を参照。承認者と指示の出典を記録する仕組みであり、本人認証ではない。

項目のdecision_idは候補作成時に生成し、同時更新するstateのchange_logと結ぶ。change_logのstatusは元の変更提案を示すproposed。実際の承認・適用・取消の状態はtransaction記録を確認する。会議を参照したことだけで、変更内容と結論の意味的一致を保証するものではない。差分の内容確認が必要。

アメリアの停止を維持し、本文・シーン進行・制御設定はこの操作の更新対象に含めない。試験の反映・取消は一時作品のみで行った。
