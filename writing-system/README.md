## 実装した範囲

Node.js 22以上、追加パッケージ不要。作品ごとの `system/series.json` で設定を読み分ける。作品の設定や原稿を共通コードに埋め込まない。

- 作品ID、設定・原稿・人物・場所・物証・決定IDの参照、重複、原稿登録漏れを検査。
- 所持品と保管者、知っている／知らない情報の同一文の矛盾を検査。意味が同じ別表現は読解レビューが必要。
- 作品外パスとリンク経由の作品外参照を拒否。
- 執筆停止中のwriter要求を拒否。編集・設計レビューは可能。
- キャラクター役には当人の明示された知識だけを渡す。作者用の陰謀情報を渡さない。
- 外部ワーカーは標準入出力のJSONで接続。戻り値の作品・役・要求・元データの版を確認。
- 出力は提案箱へ保存。再受信は重複保存せず、同じ要求IDの異なる結果は拒否。
- 外部処理の失敗、時間切れ、不正JSON、過大出力を検知。原稿や正本は更新しない。

## 使用

作業フォルダのルートから実行する。

```text
node writing-system/cli.mjs status amelia
node writing-system/cli.mjs check amelia
node writing-system/cli.mjs request amelia editor "執筆システムの不足をレビュー"
node writing-system/cli.mjs run amelia editor "執筆システムの不足をレビュー"
node --test writing-system/test.mjs
```

`request` は会話方式用の作業依頼を発行。`run` は設定済みの外部ワーカーへ同じ依頼を渡す。外部AI未設定の現状ではrunは明示的に失敗する。テスト用別プロセスでの通信成功を、実際のAI接続成功と扱わない。

会話側の返答も `request_id / series_id / base / role / output` を含むJSONで保存し、`accept <作品フォルダ> system/requests/<ID>.json <作品内の返答JSON>` で提案箱に取り込む。

## 作品の分離

共通基盤は `writing-system/`、アメリア固有のデータは `amelia/`。他シリーズは固有フォルダと固有IDを作る。既存資料は自動移動せず、出典台帳を作ってから登録する。原稿や画像、会議、感情推移を作品間で共有しない。共有するのは検査と手順だけ。

GitHubのルートREADME、develop、既存ゲーム制作には触れない。今回の共通化に限り、以前のamelia配下だけという変更範囲に `writing-system/` を追加する。

## 完成扱いにしていない部分

本バージョンは共通実行基盤の最初の実装。会議の合議結果と正本への変更承認、複数ファイルの一括反映と復旧、GitHub/Notionの通信失敗後の自動再開は未実装。外部AIの実接続も未設定。シリーズ間の共通性はアメリアと分離試験で確認した段階で、他シリーズの設計資料は未取得。

既存の `amelia/prepare_delivery.ps1` とdelivery内の古い送信用データは過去の出力。現在の完全な正本と見なさず、再送に使わない。

## 外部ワーカー契約

`series.json` の `workers` に役ごとに `{ "command": "実行ファイル", "args": ["接続用スクリプト"], "timeout_ms": 60000 }` を設定する。シェル経由では実行しない。接続スクリプトは標準入力を1件のJSONとして読み、対応するAIへ依頼して標準出力に返答JSONを1件だけ返す。鍵は環境変数等で渡し、作品ファイルやGitHubへ保存しない。設定する実行ファイルは信頼できるものに限る。

ワーカー自体はOS権限で動作するため、このプログラムは悪意あるワーカーを隔離するサンドボックスではない。プロンプトの出典判定や本文の事実性も自動保証しない。
