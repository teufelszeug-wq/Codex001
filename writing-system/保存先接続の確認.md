# 保存先接続の確認

2026-09-20。GitHub既存ファイル向け接続部 github-sync.mjs を追加した。公開済み amelia/system/series.json の読取をこの接続部から実行し、本文と blob SHA `3ba620170c02b8bd3944e7784dd064ebdc04b145` を取得した。制限内の通信は失敗し、許可された外部通信で成功。書込の実通信は未検証。

## GitHub

[公式Contents API](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents) と利用可能な接続ツールの仕様を確認。既存ファイル更新には blob SHA を指定できる。接続部はその版をそのまま送り、競合や通信失敗を自動再試行しない。新規ファイル作成はまだ扱わない。

作品設定の destinations.github から repository・branch・prefix を取得。専用prefix外、パスの遡り、developを拒否する。本文はUTF-8、API内容はBase64、通信期限は既定15秒。リダイレクトを拒否し、認証情報は実行時メモリだけで保持する。

```text
node writing-system/cli.mjs read-github amelia amelia/system/series.json
node writing-system/cli.mjs send-github 作品フォルダ 同期ID
node writing-system/cli.mjs reconcile-github 作品フォルダ 同期ID
```

send-github は実行環境の WRITING_GITHUB_TOKEN を使う。チャットや作品設定へトークンを保存しない。アプリのGitHub接続が使えても、その認証がローカル実行へ引き継がれるわけではない。sync_filesを未登録のままにした既存作品は送信計画を作成できない。

模擬通信の4試験で、日本語往復・版指定、保存領域制限、競合を再送しないこと、秘密を含む通信エラーの非公開化、新規作成／非対応形式の拒否を確認。

## Notion

[公式ページ更新API](https://developers.notion.com/reference/patch-page) と現在のNotion接続ツールを照合した。last_edited_time は観測できるが、観測した版を更新条件に指定できる保証は確認できない。old_str の部分置換もページ全体の原子的な版比較と同一とは扱わない。したがって自動同期の conditional_update を真にしない。既存ページの限定した手動更新と読み戻しは継続可能。

新規ページ作成の冪等性も未確認。重複防止のため、送信結果が不明なら再作成しない運用を維持する。Notionの全機能に保証が存在しないと断定するものではなく、今回確認した仕様では採用できないという判定。
