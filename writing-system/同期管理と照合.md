# 同期管理と照合

2026-09-20。同期の計画・送信記録・読み戻し確認を実装。実サービス用接続部は未実装。今回の試験はメモリ上の模擬保存先を使い、実際のGitHub/Notion通信の保証とは区別する。

## 操作と状態

作品の system/series.json にある sync_files で送信対象を明示し、destinations で保存先を登録する。既存作品には自動追加していない。未登録ファイルは拒否し、過去チャットの非公開資料を自動送信しない。

`node writing-system/cli.mjs prepare-sync 作品フォルダ system/同期依頼.json` で計画を作成する。依頼は source・destination・target・expected_version を持つ。既存対象は読み取った版を必須とし、新規作成は target と expected_version を null にする。

`node writing-system/cli.mjs sync-status 作品フォルダ 同期ID` で記録を確認する。送信と照合は sync.mjs の sendSync/reconcileSync を接続部から利用する。接続先未実装のため送信コマンドは提供していない。

prepared → sending → verified。保存先の変更や読み戻し不一致は conflict。通信結果が判断できない場合は uncertain。sending または uncertain の記録をそのまま再送できない。reconcileSync は読取だけを行い、新規対象を一意に見つけられなければ結果不明のまま残す。verified は記録した時点の内容一致を表し、保存先が未来にも不変である保証ではない。

送信前に現在の作品版と内容を確認する。既存対象の更新には条件付き更新、新規作成には同一操作IDでの重複防止と操作ID検索を必須とする。接続部が機能を宣言するだけでは保証の証拠にならず、各サービスの実際の動作確認が必要。Notionが必要な保証を提供しない操作は、この自動経路で実行可能にしない。

## 試験範囲と残件

8件：成功と再呼出し時の重複防止、保存先の競合、作成後の応答消失と照合、作成結果を発見できない場合、ローカル変更、対象と接続先の制限、読み戻し障害、保証を欠く接続部の拒否。

強制終了後の同期ロックの自動復旧、実サービス接続、通信期限、サービス固有の版管理、複数ファイル／ページの同期は未実装。現在のGitHub/Notion保存は別途接続ツールによる手動実行と読み戻しであり、このモジュールの実接続試験ではない。
