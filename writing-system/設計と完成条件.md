# シリーズ共通の制作工程

## 二つの運用方式

会話方式：このタスクで担当者が役別の検討を行う。外部方式：独立したプロセスを接続し、各役へ依頼を送る。どちらも同じ作品ID、版、出典、状態、提案形式を使用する。外部方式はAIサービスを特定しない。

## 制作単位

作品 → 巻／章 → シーン。原稿の版と設定の確定状態を別々に管理する。旧正式、現行正式、初稿、提案、却下、未取得を区別し、本文があることだけでは正式に昇格させない。

## 会議の必須記録

会議ID、作品ID、対象シーン、基準版、議題、参照資料、役別意見、代案、反対意見、決定ID、保留、担当、実際の実行方式、承認根拠。担当者が複数観点を書いた場合は単独レビューと表示する。

## 記憶の構成

1. 正本設定：人物、世界、宗教、魔法、固有名、出典、確定状態。
2. 時系列：出来事、時刻、場所、移動、物の受渡し、各人物が知った時点。
3. 感情：シーン前後の期待、恐れ、関係性と持ち越し。
4. 文体：視点、口調、比喩、反復、禁止表現。
5. 制作履歴：会議、決定、本文の版、レビュー、差し戻し。
6. 画像台帳：実ファイル、生成元、衣装、時点、採用状況。現物がなければ未取得。

## 安定運用の完成条件

- 作品を明示してから各工程を開始し、他作品の設定や保存先に書けない。
- 停止指定が会話・外部方式の両方で尊重される。
- 会議から決定、原稿、状態変更へ根拠をたどれる。
- 提案から確定への昇格に、誰が何を根拠に承認したかを残す。
- 検査に失敗した変更は正本へ反映しない。中断時は前の版へ戻せる。
- 保存先はGitHubの正本、Notionの閲覧・編集提案用ページとして役割を明記し、無条件の双方向上書きをしない。
- 同期は保存先ごとの版と成否を記録する。通信結果が不明な新規ページ作成は再作成せず照合する。
- 保存内容を読み戻して一致確認する。外部編集との競合は保留し、上書きしない。
- 通常、停止、誤った作品、古い版、重複、通信失敗、復旧の試験を通す。
- 実AIを少なくとも1つ接続したレビュー試験と、2作品以上の独立運用を確認してから「両方式対応完成」とする。

## 過去システム案の追加要件（2026-09-21照合）

- 文体・感情の変遷を比較する場合は、作品ID、原稿の版、対象範囲、指標の定義、測定方法、根拠箇所を記録する。機械的な文字数と解釈を伴う評価を区別する。値がなければ未測定とする。モデルの再学習を実施していない改善履歴を「学習済み」としない。
- 改善提案は、適用前後と採用／却下の根拠を追跡する。文体を一定の比率へ自動で均一化しない。
- 参照キャッシュは作品・基準版に紐づく再生成可能な派生データとして扱う。正本より優先しない。導入効果は同条件の実測で確認する。現在未実装。
- 原資料の訂正・撤回・旧版関係を記録し、後から旧集約の「確定」見出しを読んでも現行へ戻さない。監査文書での記録は開始済みだが、自動的な訂正関係の追跡は未実装。
- 画像はプロンプト、生成ファイル、検査結果、採用、分離レイヤーの実体を分ける。文章上の「誤差ゼロ」「レイヤー完成」を実物検査に代用しない。

## 実装順序（継続）

共通検査・停止・接続契約 → 会議と承認付き変更管理 → 一括反映と復旧 → 同期管理 → 実AI接続 → 他シリーズの移行試験。小説本文の再開はその後のユーザー指示を待つ。
