# 承認付き設定変更と復旧

2026-09-18。現在の対象は作品のstate.jsonに相当する設定データ1ファイル。本文・世界設定・画像など複数ファイルの一括更新は未実装。

## 流れ

1. 現在の版に対する会議を発行し、各役の意見・反対意見・保留・結論を保存する。
2. 変更案のstateとmetadata（理由、meeting_id、decision_ids）を作品内のJSONに保存する。
3. propose-changeで提案を登録する。別の検査用領域で変更後の状態を検査し、正本はまだ変更しない。
4. approve-changeで承認者と根拠を記録する。承認はその提案の内容にだけ適用される。
5. apply-changeで再検査し、版の一致を確認して設定ファイルを置き換える。変更前後を記録に保持する。
6. 必要ならrollback-changeで元へ戻す。反映後に別の変更があれば、上書きを避けて拒否する。

```text
node writing-system/cli.mjs propose-change amelia system/変更案.json
node writing-system/cli.mjs approve-change amelia 変更ID system/承認.json
node writing-system/cli.mjs apply-change amelia 変更ID
node writing-system/cli.mjs rollback-change amelia 変更ID system/取消根拠.json
```

承認・取消根拠の形式は `{ "actor": "承認者", "source": "実際の指示・会議・承認への参照" }`。この機構は記録と検査であり本人認証ではない。AIが根拠を捏造してユーザー承認と記録してはいけない。既存のユーザー指示で許可された運用修正は、その指示を根拠に記録する。

## 停止と異常処理

- 本文停止中はシーンの追加や現在シーンの移動をこの経路でも拒否する。
- 提案後に世界や原稿・設定が変わったら、その提案の承認・反映を拒否する。
- 同時の設定変更はロックで拒否する。
- 正本を書き換えた後、完了記録の保存前に中断した場合は、適用を再実行すると内容一致を確認して完了記録を補う。
- 実行プロセスが強制終了するとロックが残る場合がある。時刻だけで解除しない。所有プロセスが終了していることと、変更記録・現状を確認して復旧する。ロックの自動解除は未実装。
- 検査用コピーと変更前後の記録は保持する。取消操作の途中でプロセスが停止した場合の自動復旧、電源断に対する完全な耐久性は未検証。

## 限界

構造検査は物語の意味や心理の正しさを保証しない。承認された設定の変更も読解レビューが必要。悪意ある同一OSユーザーや外部エディタによる同時書換えを防ぐ隔離機構ではない。
