# 企画から制作会議へ

新シリーズを作成した後、quick（核だけ）、guided（質問に沿う）、full（詳細）の3段階で企画案を作る。ジャンル名は自由入力。複数ジャンルの重みは合計100にする。未定なら空配列のままでよい。

## 操作

```text
node writing-system/cli.mjs brief-template 作品フォルダ guided
node writing-system/cli.mjs save-brief 作品フォルダ system/企画入力.json
node writing-system/cli.mjs brief-council 作品フォルダ 保存で得た企画ID
```

最初の出力を作品フォルダの system/企画入力.json に保存し、answers の回答と source_ref（依頼や資料の参照先）を入力する。シリーズIDは変更しない。回答は少なくとも1項目必要。入力していない回答は未回答として残し、他作品の値で補完しない。

save-brief は system/briefs/ に新しいIDで未確定案を保存する。企画を修正したら新しい案として保存する。brief-council はその企画をソクラテス・マキャヴェッリ・ケインズ・編集者・整合性担当へ渡す。依頼を発行する操作であり、担当AIがすでに回答したことを意味しない。

会話方式では依頼を読み、同じAIが役別に検討した旨を示して返答する。外部方式は既存の外部ワーカー接続を利用するが、実AI接続は未設定。返答は既存の finish-council へ渡す。設定への採用は別の承認付き変更工程で行う。

## 検証と残件

4試験：3モードの空の質問、未回答保持と全会議担当への引き渡し、作品違い・不明項目・不正配分・出典なしの拒否、変更済み作品版と改変企画の拒否。企画保存と会議発行の前後で正本の版が変わらず、執筆停止を維持することも確認。

企画案の比較、ユーザーによる実作品企画、実AIでの返答、承認後の世界設定への対応付けは未完了。試験用作品は一時領域だけに作成し、アメリア・タケシ・イレーネの設定は追加していない。

## 企画入力画面（追加）

`node writing-system/planning-server.mjs 作品フォルダ` で起動し、http://127.0.0.1:12902 を開く。画面上の作品名・ID・保存先を確認し、回答と出典を入力して保存する。保存後に「保存した企画を会議へ渡す」を押す。入力を変更した場合は再度保存が必要。対象作品は起動時に固定する。新作品そのものの作成は既存init操作を使う。

ローカルHTTP試験2件と企画4件が通過。保存・同じ操作IDの再送・会議への引渡し・正本不変、外部Originやトークン不備、作品違い・古い版の拒否を確認した。ブラウザーでの一連の操作と目視確認は未検証。

画面には自動再送を設けない。結果不明時は操作を止め、system/briefs と system/councils の記録を照合する。サーバーは127.0.0.1のみで待ち受け、作品本文を変更するAPIは提供しない。

2026-09-21：操作ID・入力ハッシュ・開始／完了・結果を system/operations に永続保存する方式へ更新。完了した同一操作は結果だけを返し、未完了は照合待ちとして再実行を拒否する。入力内容の違う同一IDも拒否。作品版が変わっている場合は再送を拒否する。新しいサーバーインスタンスで同じ保存を再送するHTTP試験、部分処理後の例外を模擬する試験など関連5件が通過。

この検証はOSプロセス強制終了や停電耐性まで証明していない。完了記録は通常の原子的置換であり全ディスク書込の永続性保証ではない。未完了操作の自動照合・回復画面は残件。入力検査エラーでも開始後に起きた場合は保守的に照合待ちになる。ブラウザー再読込後に新しい操作IDで同じ内容を送った場合の意味的な重複検知も未対応。
