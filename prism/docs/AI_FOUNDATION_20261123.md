更新日：2026-11-23。対象は本紙・りお・専門AI17名の計19予想枠。篠宮律は司会・編集統括で別枠。

今回の範囲は、役割・入力・判断・出力・振り返りの定義と既存予想処理への接続。全AIの実レース独立予想や学習反映の完成を示すものではない。

## 共通の実行手順

1. 対象レースと公式全頭を確定し、ID・省略しない馬名・取消・公開時点を確認する。枠順前は馬IDを保持する。
2. 担当別の必要資料を収集する。映像はURL・対象日・確認場面・所見と解釈を分ける。児玉栞には過去予想と公式結果、改善ルールの検証と適用根拠を渡す。
3. 各担当が全頭を評価し、印または不足が具体的な見送り、100円買い目または見送りを保存する。
4. 一次予想を基に5議題以上の座談会を行い、担当別の維持・変更理由を付けた最終予想を保存する。前日版を先に確定し、当日は差分を追記する。
5. 公式結果・払戻を保存済み版に照合して精算し、反省候補と検証済みの採用ルールを分ける。発走後資料を発走前版に戻さない。

## 機械接続と状態表示

- 予想実行時に定義と名簿の全件一致を検証し、担当の入れ違い・欠落・司会の予想者化を拒否する。
- 各APIリクエストへその担当の定義を渡す。一次予想は本人の資料から作り、最終予想には座談会と本人の一次版を渡す。
- 新規レコードに定義版と定義hash、input_readiness、assessment_coverage、decision_status、ticket_statusを保存する。
- 入力状況はNOT_CHECKED、MISSING_INPUT、PARTIAL_INPUT、INPUT_AVAILABLEを区別。診断は既存ローカル評価が入力を使えた範囲を表し、専門モデルの性能認定ではない。
- PREDICTEDとPASSED_WITH_REASON、ローカル計算と外部API、定義済みと実行済みを別々に集計する。1名の資料不足を全員の一次予想停止の条件にしない。
- API担当別再開のキャッシュには定義hashを含め、定義が異なる応答を流用しない。既存の保存済み版を上書きしない。

~~~bash
node prism/scripts/run_forecast_panel.mjs --check-agents
node prism/scripts/run_forecast_panel.mjs --check-agents --card racecard.json --evidence specialist-evidence.json
node prism/scripts/run_forecast_panel.mjs --check-runtime
~~~

診断は予想やAPIリクエストを実行しない。出馬表なしでは全担当の入力状態をNOT_CHECKEDにする。APIキーは表示しない。
