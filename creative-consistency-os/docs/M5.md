# M5 — Isekai Pack

## Objective

Add an opt-in genre pack for secondary-world / isekai fiction that protects immersion and validates structured world constraints without turning the product into an authoritarian prose rewriter.

M5 is built on the M4 Core Lint contract and M4.5 Change Impact infrastructure. It does not create a separate diagnostic system.

## Design-review meeting

### Socratic review

The question "Is this word wrong in an isekai?" has no universal answer. A portal fantasy may intentionally mention smartphones; a translated narrative may deliberately use modern units; a comedy may use Earth names as a joke.

Result: M5 is explicitly opt-in. Every category is independently selectable, terms can be allowlisted, custom terms can be added, strictness can be changed, and no Finding rewrites prose automatically.

### Strategy review

The differentiator is not a static forbidden-word dictionary. The useful product loop is:

Earth-origin surface → concept → generic fallback → author-approved world term → source-place provenance → downstream impact.

Result: Earth-Origin Guard and World-Origin Mapping are connected to Story Bible places and M4.5 dependency tracking.

### Systems review

Travel, magic and economy should not depend on an LLM guessing numerical facts from free prose every time. Deterministic checks should be grounded in structured author data.

Result: M5 defines explicit Story Bible attribute contracts for travel events, spell costs, item prices and healing capabilities. These rules are reproducible and cheap to rerun.

### Guest — fantasy editor / conlang-worldbuilding specialist

A replacement name should come from world history, geography, language and trade rather than random syllables. Also, not every Earth-looking term needs the same treatment.

Result: M5 stores author-approved mappings and optional source-place entities. The system can suggest a generic concept label, but it does not fabricate a Canon world name or silently promote one.

## Opt-in policy

A project starts with M5 disabled.

Selecting an isekai genre does not silently enable the pack. This preserves the project-wide rule that genre choices are recommendations and configuration context, not compulsory behavior.

When enabled, the project can choose:

- soft → Earth-origin findings default to HINT
- standard → WARNING
- strict → ERROR

M4 rule-level severity settings can still override pack defaults.

## Earth-Origin Guard

Current built-in categories:

- geo_origin_food_drink
- earth_culture_food
- modern_technology
- modern_institution
- earth_currency
- modern_measurement

The first four are enabled by default inside an enabled M5 pack. The more context-sensitive currency and measurement categories default to disabled to reduce false positives.

The pack includes an initial curated catalog with examples such as:

- じゃがいも / ジャガイモ
- ウインナー / フランクフルト
- ハンバーグ
- ダージリン / セイロン / アッサム
- キリマンジャロ / モカ / マンデリン
- シャンパン / コニャック / ボルドー / ブルゴーニュ
- サンドイッチ / ナポリタン / カレー
- スマホ / スマートフォン / インターネット / SNS
- コンビニ / サラリーマン / 株式会社
- ドル / 円
- キロメートル / メートル / キログラム / 摂氏

This catalog is an immersion-assistance list, not a claim that every occurrence is historically or linguistically invalid in every fictional setting.

### Finding

Rule:

- isekai_earth_origin_term

Evidence includes:

- matched term
- category
- concept key
- generic replacement
- configured world replacement
- source-place entity id
- strictness
- pack id

Exact source offsets are preserved by scanning the original manuscript string instead of using normalized-text offsets.

## Allowlist and category controls

Authors can:

- disable any category
- allowlist individual terms
- add custom Earth-origin terms
- attach a generic replacement
- assign a custom severity to a custom term

This supports settings such as "metric units are part of the translation convention" while keeping place-derived tea names strict.

## World-Origin Mapping

A replacement mapping contains:

- earth_term
- world_term
- optional source_place_entity_id
- notes

Example:

ダージリン → 霧峰茶 → source place: 霧峰

The API and UI provide replacement preview.

If require_world_mapping is enabled and a detected Earth-origin term has no approved mapping, M5 emits:

- isekai_world_term_unmapped

The system never auto-applies the replacement to manuscript text.

## M4.5 provenance integration

A world replacement with a source-place entity creates dependency edges:

BibleEntity(source place)
→ IsekaiReplacement
→ ManuscriptDocument

Edge types:

- isekai_replacement_source
- isekai_replacement_usage

Therefore, changing the producing region can reveal manuscript chapters that use the associated world-origin term.

This was added during implementation review as M5-S13 because provenance without downstream impact would be incomplete.

## Structured travel contract

Story Bible event entities may define:

attributes.isekai_travel:
- from_entity_id
- to_entity_id
- mode
- duration_hours

M5 travel routes define:

- from / to Bible entities
- mode
- min_hours / max_hours
- bidirectional flag

Rules:

- isekai_travel_route_unknown
- isekai_travel_duration

This lets the system flag a two-hour horseback trip when the configured route requires six to ten hours.

## Structured magic contract

Spell entities may define:

attributes.magic:
- tier
- cost:
  - type
  - value

Magic policy supports:

- enabled
- require_cost
- allowed_cost_types
- costless_tiers

Rules:

- isekai_magic_cost_missing
- isekai_magic_cost_type

This prevents a spell from silently becoming free or switching to an unconfigured resource type without author review.

## Structured economy contract

Item entities may define:

attributes.economy:
- category
- currency
- price

Economy policy supports:

- registered currencies
- category-specific price bands

Rules:

- isekai_currency_unregistered
- isekai_price_out_of_band

This is not an attempt to simulate an entire economy. It is a consistency layer over author-defined ranges.

## Healing limits

Spell entities may define:

attributes.healing:
- resurrection
- limb_regrowth

Policy can independently allow or forbid these capabilities.

Rule:

- isekai_healing_limit

This protects one of the most common fantasy consistency problems: a healing system whose later capabilities accidentally invalidate earlier stakes.

## Change Impact integration

Saving M5 configuration queues:

source_type: IsekaiPackConfig
change_kind: ISEKAI_PACK_CONFIG_UPDATED

Because a global pack-policy change can affect every chapter, M4.5 handles this source type with a project-wide M4 lint rerun rather than pretending the change is local.

BibleEntity invalidations remain selectively revalidated through the dependency graph.

## Planning consequences

No new top-level milestone is required.

M6 Noble Lady / Palace-Harem / Romantic Comedy packs should follow the same pattern:

genre state model → deterministic rule → M4 Finding → M4.5 invalidation → author triage.

M7 Mystery / SF can add higher-order evidence and assumption graphs, but should keep deterministic structural checks distinct from advisory AI-semantic findings.

At M9 Closed Beta, the Earth-Origin catalog must be measured for false-positive rate. One-character or translation-convention terms should not be expanded aggressively without data.
