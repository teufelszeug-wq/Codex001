# M3 — Story Bible + Writing Room

## Objective

Turn the world-building substrate into a real writing workspace: the author can maintain a structured Story Bible, write chapter documents, autosave safely, inspect revision history, restore earlier text, and maintain a basic timeline without allowing extracted or generated material to silently become Canon.

## Design-review meeting

### Socratic review

A "fact" in a creative project is not a single state. An author's idea, an imported claim, an AI inference, a disputed statement, and an approved canonical fact have different epistemic status.

Result: M3 makes Canon state explicit and keeps the existing DRAFT / PLAN / CANON / INFERENCE / DISPUTED / DEPRECATED / ARCHIVED / REJECTED model. Ordinary entity editing cannot change Canon state. Canon promotion uses a dedicated endpoint and requires an author reason.

### Strategy review

A generic rich-text editor is easy to replace. The defensible workflow is the connection between manuscript, provenance, Story Bible, timeline, revisions and future Lint.

Result: Story Bible records source type/reference, manuscript revisions are persistent, and all material changes enter ChangeLog.

### Systems review

Autosave can create an unbounded stream of identical snapshots.

Result: manuscript content is SHA-256 hashed. Autosave only creates a new revision when title or content actually changes. Status/order changes remain saveable without producing redundant text revisions.

### Guest — serial-fiction editor / narrative-tool architect

The Bible cannot live several screens away from the prose. Writers need the manuscript, setting reference, timeline and revision recovery in the same working context.

Result: the M3 Writing Room places chapter navigation, editor, revision history, Story Bible and timeline in one author-facing workspace.

## Story Bible

Initial entity types:

- character
- place
- organization
- item
- concept
- spell
- faction
- creature
- event
- other

Every entity keeps a stable id, canonical name, type, summary, extensible attributes, Canon state, source type and optional source reference.

A normal update request is rejected if it attempts to change Canon state. The dedicated transition route validates allowed transitions and requires a reason, preserving author agency and an auditable trail.

## Writing Room

The author can create multiple manuscript documents and order them as chapters/scenes.

The current implementation stores plain manuscript text rather than introducing a proprietary rich-text format. This keeps the storage contract simple for future export/import and Lint.

The web editor currently uses a 1.2 second debounce before autosave. This is a UI policy rather than a Canon rule and can later become configurable.

## Revision model

Each manuscript begins at revision 1.

A new revision is created when:
- title changes, or
- manuscript text changes.

Identical autosaves do not create duplicate revisions.

Restoring an older revision does not erase history. The restored text becomes a new head revision.

## Basic timeline

Timeline events store:
- title
- author-defined start/end labels
- sortable numeric key
- description
- linked Bible participants
- Canon state
- source type

Participant ids must reference existing Story Bible entities. This establishes the first cross-domain integrity check needed by later Lint.
